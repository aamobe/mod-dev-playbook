# 游戏 Mod 通用开发方案

一套给游戏 Mod 项目用的开发流程，配合 AI 编程助手使用。只有两个文件：

| 文件 | 作用 | 怎么读 |
| --- | --- | --- |
| [AGENTS.md](AGENTS.md) | 项目档案、命令、禁止事项、硬规则、流程、目录 | 助手每次会话都读。约 190 行 |
| [总方案.md](总方案.md) | 全部细节：各步骤的做法、模板、按领域的设计经验、技术资料、参考仓库总结 | 按 `AGENTS.md` 的目录找到小节标题，再搜标题去读那一节，不需要通读。约 2000 行 |

## 怎么用

1. 把两个文件复制到 Mod 项目的根目录。
2. 填 `AGENTS.md` 里的 `project` 和 `cmd`：游戏和加载方式、各个目录、编译和检查各跑什么命令、什么输出算通过。带 `<…>` 的都要换掉，用不上的行删掉。
3. 在 `rules.project` 里写上这个项目特有的边界。
4. 之后按 `AGENTS.md` 的 `route` 判断一件事走哪条流程，按 `steps` 和 `index` 去总方案里查做法。

## 这一份和项目里那一份的关系

- **复制进项目之后，项目里的那一份就是那个项目的开发依据**，可以按项目的情况改。
- **这个仓库里的是通用参考**，不会自动同步到各个项目，各项目也不必追着它更新。
- 通用版有了值得要的更新，由项目自己决定取哪几条；项目里发现值得推广的做法，手动提回这里，并在总方案的“修订记录”里记一行。

## 内容从哪来

- **实战经验**：《Probably Stolen》的 Mod “公司增强”（[aamobe/CorpPresence](https://github.com/aamobe/CorpPresence)）从 0.3.3 到 1.0.0 的开发指南和 40 个问题复盘。条目后括号里的编号（如 B07）是那个仓库的案例号。
- **早期约定和技术资料**：两个练手项目（Unity IL2CPP、Godot）里验证过的做法，标【实测】。
- **流程建议**：从 20 个方法类仓库里提炼的做法（superpowers、spec-kit、OpenSpec、决策记录、RFC、约定式提交等），总方案附录 J 有各仓库的总结，第十章说明每个做法的出处。

## 现状

- 标“（建议）”的步骤还没有在实际项目里完整用过，按情况取用。
- 实际用过的部分：开工前对远端、基线确认、分层汇报、决策记录、更新日志、提交信息格式、发布物与源码的反编译对比。
- 技术资料主要覆盖 Unity（Mono、IL2CPP）和 Godot；换引擎或加载器后，原则可以照用，具体接口和时序要重新核对。
- `AGENTS.md` 是写给助手读的结构化文本，没有用解析器验证过，不保证能被程序严格解析。
- 还没有一个从头走到尾的完整例子。
